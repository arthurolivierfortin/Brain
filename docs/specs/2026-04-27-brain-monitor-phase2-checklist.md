- [ ] [SPEC-4] In `brain.html`, add the simulation-tick + render loop to `<BrainGraph>`. Implement `simulate(nodes, edges, size, dragNode)` exactly as described in spec §"Force-directed simulation algorithm" (5 phases: repulsion, spring, center gravity, cluster gravity, damping/integration/bounds). Implement `render(ctx, nodes, edges, view, activatedAt, focus)` exactly as described in spec §"Render loop" (edges, halos, nodes, focus highlight). - [ ] [SPEC-5] In `brain.html`, add click-to-focus to `<BrainGraph>`. On `mousedown` over the canvas, convert client coords to world coords via `((clientX - rect.left) - view.x) / view.k` (and same for y). Iterate `nodes` and find the closest one within `node.size + 4` px Euclidean distance. If a node was hit AND the subsequent drag (mousedown → mouseup with no move ≥ 3 px) qualifies as a click, toggle `focus`: `setFocus(focus === node.id ? null : node.id)`. Clicking on the empty background sets `focus = null`. Clicking again on the same focused node clears it. **Manual verification anchor:** click a node in `/monitor`; node gets a white outline; thought stream filters to events for that node; click empty space → focus clears, stream shows all events again. — `backend/src/brain/static/brain.html`

- [ ] [SPEC-6] In `brain.html`, add drag-to-pin to `<BrainGraph>`. On `mousedown` over a node (same hit-test as [SPEC-5]), set `dragNodeRef.current = node` and on each `mousemove` update `node.fx = wx; node.fy = wy` in world coords; the simulation's integration step (already in [SPEC-4]) honors `fx/fy` by snapping `n.x = n.fx; n.y = n.fy`. On `mouseup`, clear `dragNodeRef.current = null` AND set `node.fx = node.fy = null` (release the pin — temporary, not persistent, per spec). If the mouse moved less than 3 px between down and up, treat as click instead (handled in [SPEC-5]). Drag and pan are mutually exclusive: a `mousedown` either starts a drag (node hit) or a pan (background hit), never both. **Manual verification anchor:** click and hold on a node, drag it across the canvas; node follows cursor; release → node remains where dropped briefly, then drifts under simulation forces. — `backend/src/brain/static/brain.html`

- [ ] [SPEC-7] In `brain.html`, add pan + zoom to `<BrainGraph>`. On wheel over the canvas: `factor = Math.exp(-e.deltaY * 0.001)`, `newK = clamp(view.k * factor, 0.4, 3)`. Zoom toward cursor: convert cursor screen coords to world coords using current `view`, then update `view.x` and `view.y` so the same world point stays under the cursor at the new scale. On `mousedown` over background (no node hit): start pan, capture `panStart = { x: clientX, y: clientY, vx: view.x, vy: view.y }`. On `mousemove` while panning: `view.x = panStart.vx + (clientX - panStart.x); view.y = panStart.vy + (clientY - panStart.y)`. On `mouseup` or `mouseleave`: clear pan. The view is held in `useRef` (no React re-render per frame); the rAF loop in [SPEC-4] reads `view` directly. **Manual verification anchor:** scroll wheel → zoom toward cursor; click+drag empty background → graph translates; cursor changes to `grab` / `grabbing` appropriately. — `backend/src/brain/static/brain.html`

- [ ] [SPEC-8] In `brain.html`, refine the edge rendering inside `<BrainGraph>`'s `render()` per spec §"Render loop". When `focus` is set, build `edgeFocusSet = new Set([focus, ...neighborsOf(focus)])` once per frame so per-edge lookup is O(1). **Manual verification anchor:** with no focus, edges are dim grey by default and brighten when one endpoint was just touched by a recent event; with focus on a node, edges to its neighbors are bright accent-colored, all other edges fade to ~5% opacity. — `backend/src/brain/static/brain.html`

- [ ] [SPEC-13] In `brain.html`, implement `useTimeline()` hook + `<ActivitySparkline>` component. Hook: `useEffect` + `setInterval` at 60000 ms, fetches `/events/timeline`, returns `{ buckets, lastError }` where `buckets` is the array of 24 dicts (or `[]` when backend returns empty). Pauses on `document.hidden` (not on `tweaks.running` — sparkline is too cheap to bother). Component: inline SVG, `viewBox="0 0 120 16"`, 24 stacked bars × 4 px wide, 1 px gap. Each bar's stack from bottom up: `archived` (grey), `merged` (yellow), `reinforced` (blue `#7da9d8`), `searched` (cyan), `stored` (green). Bar height for type t in bucket i = `(bucket[t] / max) * 16` where `max = Math.max(1, ...allBucketTotals)` (the `Math.max(1, ...)` guards against div-by-zero when all zeros). When `buckets.length === 0` OR all totals are 0, render a single `<rect width="120" height="16" fill="var(--dim)" opacity="0.2" />` and no bars. Mounted as the rightmost child of `<Header>`. Hover on any bar shows a small floating div (absolute-positioned tooltip near the bar) with the per-type counts for that bucket. **Manual verification anchor:** after a few minutes of session traffic, the header right side shows a 24-bucket bar chart with non-zero stacked colors; on a fresh brain with empty event log, the strip is uniformly grey. — `backend/src/brain/static/brain.html`
